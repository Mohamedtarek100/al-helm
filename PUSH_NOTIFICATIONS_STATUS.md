# Study reminder delivery status
The current build provides an in-app notification center and editable reminder preferences, but does **not** schedule background reminders or deliver Web Push. The service worker's push event handler only displays a received payload; it is not a sender or scheduler. The account requires a real HTTPS deployment and Supabase project before the secure path can be completed.

For a $0 TWA/PWA deployment, the remaining secure implementation must register Push API subscriptions after explicit permission, store each authenticated user's subscription under RLS, create VAPID keys and keep the private key exclusively in a trusted server-side function, and run an authenticated scheduler that selects due reminders and atomically claims an idempotency key before sending. It must honor timezone, quiet hours, preferences, completion/cancellation, and reschedule changes. Test with the browser/device subscription; backend queueing alone is not delivery confirmation. No such sender/scheduler or physical Android device test is configured in this checkout, so background delivery is not claimed.
