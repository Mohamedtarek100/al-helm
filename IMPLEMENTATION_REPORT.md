| # | Reported symptom | Root cause (verified in code and in the running app) | Fix |
|---|---|---|---|
| 1 | Tasks "not reliably saved" | `persistCloudSnapshot` catch block checked `cloudActive` **before** `localSaved`. A failed DEVICE write while cloud mode was active returned `'local'` → "saved on this device" for a task that existed only in memory. | Device-write failure is now always a real error. Regression test `taskCreation.test.ts` → "reports a real failure when the DEVICE write fails while cloud mode is active". |
| 2 | Alarms make a silent notification | Every tone pointed at `content://settings/system/...`. Those URIs resolve to SILENCE on ROMs whose default notification sound is None, and `effect_tick` is routinely muted for channels. | Bundled, synthesised WAVs in `android/app/src/main/res/raw` (`ulife_chime/bell/alarm/notification.wav`), generated by `scripts/generate-alarm-tones.mjs`. Versioned channel ids `4ulife-reminders-*-v2` (Android never changes a created channel's sound). Legacy ids re-created with audio. |
| 3 | Deleted notifications come back | `deleteNotification` RESTORED the item whenever the write was not a *cloud* write, even though the dismissal was already queued — and the queue was never used to filter incoming feed rows. | Queued dismissals now filter feed rows (`if (dismissedIds.has(row.id)) continue`), and a queued deletion is treated as durable (never restored). |
| 4 | Announcements leak across accounts | The local recovery snapshot carries the previous account's announcements; `authenticate` restored them. A dismissal error from account A was also rethrown into account B's sync. | Server announcements are dropped on `authenticate` and on `logout`; `pendingAnnouncementDismissalError` is cleared on authentication; `syncServerAnnouncements` requires a verified userId. |
| 5 | Admin page goes very dark / buttons dead | `.ac-drawer-backdrop` (`position: fixed; inset: 0`) was a BLOCK-level child of a BLOCK `.ac-drawer-layer`, so it painted ON TOP of the panel and pushed `.ac-confirm` beneath a 70 % scrim. | `.ac-drawer-layer` is a flex container (`--sheet`, `--confirm`); backdrop at z-index 0, panel/dialog at z-index 1, `isolation: isolate`. |
| 6 | Studio canvas tiny / below the fold / wrong shape | Three independent defects: (a) the studio sat in page flow, so ~390px of chrome preceded it; (b) the sizing selector `.sketch-canvas.sketch-canvas` required the class TWICE and matched nothing, so legacy `width:100%; aspect-ratio:900/620` governed the box; (c) the compositor letterboxed inside a box of a different ratio. | Viewport-locked shell for the studio route; a single authoritative canvas rule using measured `--studio-stage-*`; `compositeLayers` fills the element box; `ResizeObserver` re-composites when the box settles. |
| 7 | Eraser faded instead of erasing | The eraser's opaque mask colour was routed through the feathered stamp. | `paintBrushStroke` always paints the eraser as a solid path; `inkLayers` forces `ERASER_MASK` and full opacity/flow. |
| 8 | Deleting a layer destroyed artwork | Layer delete filtered out every element on that layer. | Elements are MOVED to the surviving layer; only the layer record is removed. |

# PATCH RELEASE 1.5.9 — Confirmed production task-persistence defect

## Root cause (from the production PostgreSQL log)

```
POST /rest/v1/tasks → HTTP 400
invalid input syntax for type time: ""      SQLSTATE 22007
```

`tasks.due_time` is `TIME WITHOUT TIME ZONE` and nullable. The task form allows
an empty time and stores `''`; the generic camelCase→snake_case mapper in
`src/services/persistence/supabase.ts` carried that empty string into the
INSERT. Because the adapter writes the whole snapshot in one pass, **every**
task created without a time failed the entire save — so tasks appeared to be
"not saved" regardless of entry point.

## Fix

`src/services/persistence/supabase.ts`
- New exported `normalizeOptionalTime(value)` — blank, whitespace-only,
  `undefined`, `null` and non-string become `NULL`; real values are trimmed and
  returned verbatim (`09:30`, `14:45`).
- In the task row builder: `mapped.due_time = normalizeOptionalTime(item.dueTime)`.
- The column type, RLS and policies were **not** touched.

`src/services/persistence/coordinator.ts`
- **Recovery fix.** On cloud restore the coordinator replaced the local snapshot
  wholesale (`data: hydrateData(remote)`), so a task saved on the device but
  rejected by the server disappeared on the next cold start.
- New `mergePendingIntoRemote()`: device-only records are kept (bounded to
  records updated within 7 days), the **server always wins** for ids present on
  both sides, ids are never duplicated, and the merge is deterministic.
- New `pendingUploadCount()` exposes how many records exist only on this device.
